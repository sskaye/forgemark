How to read the ranking

The product's promise is that review data lives in the author's file without disturbing it, and that a human and an agent can work on one file together. Anything that breaks either promise ranks first, whatever its size. Bugs an expert hits in a normal session come next. Structural work ranks by how much it lowers the cost of everything after it. Hygiene is last, and mostly small.

  1. Critical

    Make commenting and editing Markdown lossless

    large, in three steps

    Every comment or keystroke rewrites the whole file in the editor's dialect. The rendered view re-serializes the entire document through Tiptap on any change, including adding one comment with no typing. A probe with the app's exact extension list changed 24 of 32 ordinary Markdown constructs. Frontmatter becomes a heading. Bare filenames are autolinked. HTML blocks and ordinary HTML comments are deleted. Hard-wrapped paragraphs are unwrapped. Reference links are inlined and their definitions dropped. Footnotes, escapes, tables' alignment, setext headings, indented code, and multiple blank lines are all normalised. A four-backtick fence around a three-backtick fence is corrupted. This is what rewrote SKILL.md during your review, and it makes a reviewed file's git diff the entire document.

    • src/components/RenderedView.tsx:244-268, 388-394 the update and applyAnchor paths both return getMarkdown() for the whole document.
    • src/components/RenderedView.tsx:193-198, 216 mark order puts bold outside the anchor, so an anchor spanning **bold** and *em* ends up with its markers inside the delimiters after one pass and shrinks to bold on the second. linkify: true plus the Link extension's default autolink produce the filename links.
    • @tiptap/extension-code declares excludes: "_", so bold and anchors are dropped from inline code at parse time. An anchor around `foo()` loses its markers entirely and the comment is orphaned by the first keystroke. The CLI creates exactly this shape when a phrase touches code.
    • src/format/markers-display.ts:21-25, 78-89 span replacement and coalescing are not fence-aware, unlike the scanner, so markers quoted inside a code fence are eaten and a stray </span> can be left in the fence. This is the mechanism that stripped the example in SKILL.md twice.
    • src/components/CodeBlockAnchor.ts:79-91 writes the block's trailing newline, so a code block inside a list gains a blank line per save; it always emits three backticks, which breaks nested fences.

    Step 1, small to medium. Stop routing Markdown comments through the editor. HTML already splices markers at byte offsets; do the same for Markdown by moving the CLI's phrase locator from cli/anchor.ts into src/format and using the captured selection text and context to find the passage in the untouched body. A reviewer who never types then gets a byte-identical file plus two markers. Make prose editing an explicit toggle, off by default, so a stray keystroke cannot normalise a file.

    Step 2, small. The cheap fidelity wins: split frontmatter off before the editor and re-attach it after; turn off linkify and Link's autolink; register a Code extension with excludes: "" after the anchor mark; make span replacement use the scanner's code regions; strip the trailing newline and size the fence to the longest backtick run in CodeBlockAnchor. Represent markers as inline atom nodes rather than a mark so an anchor can legally span formatting. Add a parity test that runs each fixture through the real extension list and compares bytes.

    Step 3, medium to large, choose one. For typing, either diff the editor's top-level blocks against the source's block map and splice only the changed run (keeps WYSIWYG; unrepresentable blocks become verbatim atoms), or edit in CodeMirror, which is already a dependency, and keep the rendered view read-only. For this userbase, CodeMirror editing is the smaller and more honest option unless WYSIWYG typing is a hard requirement.

  2. Critical

    Stop auto-save from overwriting an agent's write

    medium

    The human-plus-agent workflow can lose the agent's comment with no banner. The file watcher uses the plugin's debounced watch with its default two-second delay, plus a 200 ms debounce of its own, so an external change surfaces about 2.2 seconds after it lands. Auto-save fires 500 ms after any keystroke and never checks the disk. If the CLI writes a reply and the reviewer types within two seconds, auto-save writes over it, the watcher then reads the app's own bytes, the hash matches the refreshed baseline, and nothing surfaces.

    • src/state/DocumentBindings.tsx:468-484, 240-262 neither auto-save nor ⌘S compares the disk against the baseline before writing.
    • src/services/fileWatcher.ts:47, 84-93 calls watch() without delayMs.
    • src/services/fileIO.ts:130 the app's own write is a truncate-then-write, so a concurrent reader (the CLI's lint) can see a partial file. The CLI writes through a temp file and rename; the app should too, and needs fs:allow-rename in the capability.
    • src/state/DocumentBindings.tsx:112, 278, 478 every baseline is built with a null mtime, so the mtime fast path in conflict.ts never runs and two of its unit tests describe behaviour production never exercises.

    Before every write, stat and re-read the file and compare its fingerprint with the baseline; on a mismatch dispatch the external-change action instead of writing. Pass a short delayMs to the watcher. Write through a temp file and rename. Store the mtime in the baseline or delete the dead fast path.

  3. High

    Fix the save and quit state machine

    small each, one focused pass

    Four verified bugs in one file, all reachable in a normal session.

    • src/state/DocumentBindings.tsx:293-318, 355-373 ⌘Q with a read-only document that has an unsaved comment loops forever: runQuit finds the dirty doc, guardDiscard treats read-only as nothing to do and calls executeIntent, which calls runQuit again. Commenting on read-only files is allowed, and such a review can never be saved anywhere because Save As is also blocked by the read-only check.
    • src/state/DocumentBindings.tsx:473-478; src/state/document.ts:352-360 keystrokes typed while a save is in flight are lost: the saved action replaces body with the snapshot that was written and clears dirty, so a later edit is reverted in state and in the editor and never saved.
    • src/state/DocumentBindings.tsx:364-369 the silent save on close or quit does not check that the save succeeded; a disk-full or permission error flashes a banner and the tab closes anyway.
    • src/state/document.ts:315-344; DocumentBindings.tsx:380-415 "Save As" from the unsaved-changes prompt writes the file but never carries out the close or quit, because the load action clears the pending intent. The same action also flips a user in Source view back to Rendered and lets Save As target a path already open in another tab.

    Skip read-only documents in runQuit and let Save As proceed for them. Make saved leave body alone and set dirty from a comparison with the written snapshot. Have performSave return whether the write happened, and fall through to the prompt when it did not. Give the rebind-only load its own reducer branch that touches only path, name, original text, and dirty. Add one integration test per bug.

  4. High

    Make delete recoverable and undo consistent

    small to medium

    Delete is one keystroke, unconfirmed, and irreversible, and ⌘Z afterwards corrupts the file. Backspace with a card focused deletes a whole thread with its replies. Programmatic body replacements for delete, accept, reject, and reattach go through setContent as ordinary history entries, so ⌘Z restores the markers in the editor while the record stays deleted; the next save writes a recordless pair, and if a comment is added meanwhile its id is reused and the pair is duplicated.

    • src/components/Sidebar.tsx:84-88; FMCard.tsx:223-233, 273-283, 323-333 immediate deleteComment dispatch.
    • src/components/RenderedView.tsx:279 setContent without addToHistory: false; the undo-isolation test currently asserts the opposite intent.

    Mark programmatic replacements as not undoable in the editor, and add a small reducer-level undo that keeps the last deleted comment with its previous body and offers "Undo" in the banner slot for a few seconds. That is better than a confirm dialog for an expert user.

  5. High

    One keymap, and shortcuts that know where focus is

    small to medium

    ⌘⇧E is bound in three places and all three fire. With a saved file open and your own card focused, one chord opens the edit composer, the Clean Export modal, and Find with the selection. On macOS the native menu owns the chord, so the sidebar binding is dead in the real app. Card shortcuts listen on window whenever the reducer has a focused comment, which is also set by clicking an anchor in the editor; so ⌘⏎ while typing resolves a thread, and Backspace with the Reattach modal open deletes the comment behind it.

    • src/components/AppShell.tsx:109-112; Sidebar.tsx:70-81; EditorPane.tsx:268-278; src-tauri/src/lib.rs:202 the three bindings and the menu accelerator; the EditorPane branch lacks a shift check.
    • src/components/Sidebar.tsx:47-92 only the Delete branch checks for a typing target; none check for an open modal or DOM focus in the sidebar.
    • src/components/TabBar.tsx:29-39 inactive tabs have tabIndex -1 and no arrow-key handling, so tabs are unreachable from the keyboard.

    Move every app chord into one keymap table with a single window listener that knows about modals and the focused region. Drive card shortcuts from DOM focus by dispatching the focused comment from the card's focus event. Add ←/→ on the tab strip, ⌘⇧[ and ⌘⇧], and j/k or ↑/↓ to move between cards, which is the navigation the sidebar currently lacks.

Leave alone

The reviewers were asked what not to touch. These came up independently from more than one of them.

  • The HTML review path: byte splicing instead of re-serialization, one shared text coordinate between DOM and source, and the honest handling of WKWebView's missing events. This is the design item 1 should copy for Markdown.
  • The format layer: deterministic emitter, tolerant parse plus fail-soft recovery, and now the write-side guards.
  • workspace.ts: thin, deterministic, and tested on every branch. The undo-isolation design with loadGeneration.
  • The Rust shell: careful mutex handling, the exit-approval flag with its reason documented, the custom Quit item, platform gating.
  • The external-change state machine and its integration tests; the unsaved-work rule of saving silently when possible.
  • The build tooling: deterministic skill and CLI bundles, byte-compared by tests; version check across four files including the Cargo lock.
  • The typing-test harness that drives ProseMirror through real DOM mutation, and ARCHITECTURE.md's candour about what the suite cannot cover.

Testing strategy

The suite is strong where the format layer and reducers live and weak in exactly the places items 1 through 7 change. Every item is developed test-first: the failing test is written before the fix, so it proves the bug and then guards the fix.

  • Before item 1: a characterization test that runs each fixture through the editor's real extension list and compares bytes. It is red today for the known cases and becomes the gate for every step of the lossless work.
  • Item 3: one failing integration test per bug (quit loop, lost keystroke, failed silent save, Save As from the prompt) before each fix.
  • Item 8 before items 7 and 10: the shared harness lands first and removes the five double-mounted bindings, so the refactors lean on tests that run one save timer, not two.
  • Items 5 and 7: keyboard and modal work gets focus assertions; nothing in the suite asserts focus today.
  • Manual checklist: the things jsdom cannot reach (the real directory watcher, native menus, file dialogs, iframe layout) go in a short checklist in the architecture doc, run before a release rather than per change.

Expected cost: about a third of each change. Expected payoff: the two critical items, which touch the code paths that write files, land with proof rather than confidence.
